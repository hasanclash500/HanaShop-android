# مدیریت فروشگاه — پروژهٔ اندروید (آفلاین)

این پوشه یک پروژهٔ کامل Android Studio / Gradle است. برنامهٔ وب شما (`app/src/main/assets/www/`) بدون هیچ تغییری در منطق داخل یک WebView آفلاین اجرا می‌شود (بدون اینترنت). فایل‌های `index.html`، `app.js` و `style.css` همان نسخه‌ای هستند که آزمون شده‌اند (۳۲ آزمون حسابداری، ۱۹ داشبورد و فروش، ۲۰ قابلیت‌های جدید، ۷ صفحه‌ها).

## ساخت APK
1. Android Studio (Koala یا جدیدتر) → Open → همین پوشه. بگذارید Gradle Sync کامل شود (اینترنت لازم است).
2. Build → Build APK(s). خروجی: `app/build/outputs/apk/debug/app-debug.apk`
3. یا با خط فرمان (JDK 17+ و Android SDK 34): `gradle wrapper --gradle-version 8.7` سپس `./gradlew assembleDebug`
4. برای انتشار: Build → Generate Signed Bundle / APK و کلید امضا را **جایی امن نگه دارید**؛ با گم شدن آن، به‌روزرسانی ممکن نیست.

## فونت وزیرمتن
دو فایل `Vazirmatn-Regular.woff2` و `Vazirmatn-Bold.woff2` را در `app/src/main/assets/www/fonts/` بگذارید (مجوز OFL، قابل بسته‌بندی). `@font-face` در `style.css` آماده است. بدون این فایل‌ها برنامه با Tahoma درست کار می‌کند.

## پل‌های اندروید (در MainActivity.java)
`AndroidBridge.saveFile` (پشتیبان JSON/CSV در پوشهٔ Download)، `shareFile` (اشتراک فایل/فاکتور)، `printPage` (چاپ و PDF)، همچنین پنجره‌های تأیید/هشدار، انتخاب فایل برای ورود اطلاعات، لینک‌های واتس‌اپ/تلگرام/پیامک و دکمهٔ برگشت.

## هشدار دادهٔ کاربر
اطلاعات در IndexedDB همین برنامه ذخیره می‌شود. با حذف برنامه یا «پاک کردن داده‌ها» از بین می‌رود. پشتیبان‌گیری منظم JSON ضروری است. نصب نسخهٔ جدید روی نسخهٔ قبلی (با همان کلید امضا) اطلاعات را نگه می‌دارد.

## قابلیت‌های تازه
- **فروش سریع گرمی:** مقدار دلخواه، دکمه‌های +۵/+۱۰/+۲۰/+۵۰/+۱۰۰ گرم و جمع هر ردیف.
- **پشتیبان:** نوار هشدار روی داشبورد؛ در اندروید هنگام رفتن برنامه به پس‌زمینه، حداکثر روزی یک پشتیبان خودکار در Download ذخیره می‌شود.
- **قفل برنامه:** «بیشتر ← قفل برنامه». رمز ۴ تا ۶ رقمی (فقط هش، روی همین دستگاه) و اثر انگشت (BiometricPrompt؛ نیاز به `androidx.biometric` که در build.gradle هست).

## تولد مشتری و یادآوری ساعت‌دار در اندروید
- در «کارها و پیگیری» دکمهٔ «+ کار جدید» را بزنید؛ عنوان، تاریخ **شمسی** و **ساعت** (برای مثال ساعت ۱۱:۰۰ روز ۲۹) را وارد کنید.
- همان بخش، دکمهٔ «فعال‌کردن اعلان‌ها» را بزنید. در اندروید ۱۳ و بالاتر، تأیید مجوز اعلان الزامی است.
- برای تحویل دقیق‌تر در ساعت انتخابی، «فعال‌کردن ساعت دقیق (اختیاری)» را بزنید و مجوز Alarm & reminders را در تنظیمات سیستم بدهید. اگر مجوز داده نشود، اعلان همچنان برنامه‌ریزی می‌شود اما اندروید می‌تواند ارسال را به تأخیر بیندازد.
- برای مشتریانی که تاریخ تولد **شمسی** آنها ثبت شده و بایگانی نشده‌اند، ساعت **۹ صبح** در روز تولد اعلان گروهی دریافت می‌کنید؛ پس از بسته‌شدن برنامه نیز اعلان کار می‌کند. پس از راه‌اندازی دوبارهٔ گوشی زمان‌بندی مجدداً برقرار می‌شود. تنظیمات «باتری/بهینه‌سازی» برخی گوشی‌ها ممکن است اعلان را دیرتر نشان دهند.
- اعلان‌ها به اینترنت و سرور نیاز ندارند. متن یادآورها و نام مشتریان در حافظهٔ خصوصی برنامه برای اعلان‌های محلی نگه داشته می‌شود. اعلان پیش از کسب اجازه سیستم نمایش داده نمی‌شود.
- یادآورهای قبلی که ساعت ندارند، پیش‌فرض ساعت ۹ صبح دارند. برای تغییر زمان باید کار جدید با ساعت دلخواه ثبت شود.
- این تنظیمات مربوط به APK اندروید است؛ صفحهٔ وب مستقلِ پروژه اعلان پس‌زمینهٔ گوشی ندارد.

## ایمنی داده و پشتیبان
- «داده‌ها و پشتیبان ← ذخیره پشتیبان کامل (JSON)» را منظم اجرا کنید و فایل را به محلی خارج از گوشی (مثلاً رایانه یا فضای امن) منتقل کنید. فایل JSON حاوی داده‌های مالی و اطلاعات تماس مشتریان است؛ آن را عمومی نکنید.
- اکنون برنامه فقط **پس از تأیید نوشتن فایل توسط اندروید** تاریخ آخرین پشتیبان را ثبت می‌کند. پیش از بازیابی کامل یا مهاجرت نیز تهیهٔ نسخهٔ ایمنی لازم است؛ اگر فایل ایمنی ذخیره نشود عملیات متوقف می‌شود.
- بازیابی JSON معتبر بودن ساختار پرونده و تراز بودن تک‌تک اسناد حسابداری را بررسی می‌کند؛ فایل نامعتبر جایگزین داده‌های فعلی نمی‌شود.
- روی اندروید ۱۰ به بالا فایل‌ها در Download ذخیره می‌شوند. روی اندروید ۸/۹ ذخیرهٔ فایل در پوشهٔ اختصاصی برنامه انجام می‌شود که هنگام حذف برنامه می‌تواند از بین برود؛ حتماً فایل را به جای امن منتقل کنید.
- تغییر APK **Debug** به APK **Release** با کلید امضای متفاوت ممکن است نیازمند حذف برنامه قبلی باشد؛ قبل از هر تغییر امضا از داده‌ها نسخه پشتیبان بیرونی بگیرید.


## ابزارهای مدیریت فروشگاه (نسخه افزایشی)
در بخش «بیشتر» پنج دکمه جدید وجود دارد:
- «کنترل حسابداری»: تراز بدهکار/بستانکار، تطبیق موجودی کالا، مطالبات مشتریان و بدهی تأمین‌کنندگان با دفتر کل. اختلاف‌ها فقط گزارش می‌شوند، نه اصلاح خودکار.
- «شمارش صندوق»: موجودی دفتری صندوق و مبلغ واقعی شمارش‌شده را مقایسه و اختلاف را ثبت می‌کند. برای اصلاح حسابداری باید سند مستقل و مستند ثبت شود.
- «سود هر عطر»: سود ناخالص بر اساس ردیف‌های فاکتور، بهای تمام‌شده ثبت‌شده در زمان فروش و تخفیف متناسب محاسبه می‌شود. گزارش دوره‌ای دفتر کل مرجع نهایی است؛ فاکتورهای CRM قدیمی فاقد ردیف کالا و برخی اثرهای زمانی مرجوعی می‌توانند باعث اختلاف شوند.
- «وفاداری مشتریان»: فهرست مشتریان برتر و مشتریانی که حداقل ۶۰ روز خرید نکرده‌اند؛ ارسال پیام خودکار انجام نمی‌شود و باید رضایت تبلیغاتی رعایت شود.
- «ثبت عطر گرمی / میلی‌لیتری»: واحدهای «گرم»، «میلی‌لیتر» و «عدد» به‌صورت مجزا. مقدارها در این نسخه **صحیح** هستند؛ تبدیل جرم به حجم بدون چگالی کالا مجاز نیست. واحد کالایی که موجودی یا سابقه خرید/فروش دارد قابل تغییر نیست.

### حفظ اطلاعات و مهاجرت نسخه اندروید
- پایگاه داده همان IndexedDB با کلید shopdb/kv/db است؛ فیلد اختیاری cashCounts برای ثبت شمارش‌های صندوق اضافه شده و نسخهٔ دادهٔ قبلی همچنان پشتیبانی می‌شود.
- پیش از به‌روزرسانی یا حذف نسخه قبلی، «داده‌ها و پشتیبان ← ذخیره / JSON ← ذخیره پشتیبان کامل» را بزنید؛ فایل JSON را روی کامپیوتر کپی و سالم بودن آن را بررسی کنید.
- **APKهای Debug تولیدشده در اجراهای مختلف GitHub Actions معمولاً کلید امضای یکسان ندارند و ممکن است به‌صورت به‌روزرسانی روی هم نصب نشوند.** اگر نصب نسخه جدید به‌دلیل امضا رد شد، برنامه قبلی را قبل از گرفتن پشتیبان معتبر حذف نکنید. برای به‌روزرسانی‌های دائمی باید APK Release با کلید امضای ثابت و محرمانه ساخته شود.
- بازیابی کامل، قبل از جایگزینی اطلاعات، نسخه ایمنی می‌سازد و اسناد را بررسی می‌کند. بعد از بازیابی، کنترل حسابداری را اجرا کنید.
- هنگام پاک‌کردن همه داده‌ها، عملیات تا زمانی که ذخیره فایل پشتیبان موفق نشده باشد متوقف می‌شود.
- ورود «فقط کالاها» از JSON اکنون ارزش افتتاحیه موجودی را در سند متوازن حسابداری ثبت می‌کند.
